## MIRA 2.2.1

MIRA can now keep running in the background: close the window and new mail still syncs and notifies you.

2.2.1 is the first published build of the 2.2 line (the 2.2.0 tag was never released): it also fixes the Linux build on older GLib (Ubuntu 22.04, Debian 12) and adds an experimental Windows build.

### What's new
- **Background daemon (Linux).** A new `mira-daemon` owns the mail engine and runs as a `systemd --user` service. The app asks once, on first launch, whether to keep MIRA active in the background (default: yes). You can change it later in Settings → Notifications. Answering no still works: the app starts the daemon on demand and it stops 30 seconds after the last window closes.
- **Desktop notifications from the engine.** New-mail notifications now come from the daemon, so they keep arriving with the window closed. Content, sound, quiet hours, muted accounts and "notify when MIRA is focused" are engine settings, shared by every client. Android and the embedded fallback show the same notifications through the app.
- **Tray icon.** A notification-area icon with *Open MIRA*, a status line and *Quit MIRA*. It is simply absent on desktops without a notification-area host (for example GNOME without the extension).
- **Test button.** Settings → Notifications → *Send a test notification* asks the daemon to display one.
- **Locked keyring.** If the system keyring is locked at login, the daemon waits, retries and syncs again as soon as it is unlocked, with a single notification.
- **Safe updates.** When the app and the running daemon differ in version, the daemon is restarted automatically if no other client is attached, and the app asks first otherwise.
- **Compose fixes.** Sending is refused when the last draft save failed, the recipient field rejects addresses the engine would reject, and you get a warning when your message mentions an attachment but has none.
- **Local labels** export and import now carry their settings.

### Packaging
- The `.deb`, `.rpm`, `.tar.gz` and Arch packages ship `mira-daemon` and its systemd user unit. A single-user install through `install.sh` places the unit in `~/.config/systemd/user/`.
- **Windows (experimental):** a portable `.zip` with the embedded engine (no background daemon yet). It is unsigned, so Windows SmartScreen will warn on first launch. macOS is not part of this release.

### Upgrading and known limits
- After upgrading, the first launch asks the background question. Existing notification preferences are copied into the engine once.
- The daemon's TCP transport (loopback only) uses a plain-text token; TLS and pairing are planned with remote engines.
- Notification texts are available in French and English and follow the system locale.
- Flatpak and Snap builds are not part of this release.
- Android APKs are signed with the debug key: fine for direct installs, not for the Play Store.
