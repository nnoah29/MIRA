## J6 — Lectures locales, vues calculées, fils

Références : D-12, D-14, D-15, 7.10, 9.3, 9.7, 12.2.1, 12.4 (Messages lecture, Fils, Recherche et vues), S6, S11 ; invariants 12, 13, 27, 29.

Module `mira-core/src/reading/` (lectures) et `mira-core/src/threads/` (fils). Toutes les lectures passent par la base locale, **jamais par le réseau** (invariant 27).

1. `ListQuery { view: ViewRef, filters: MessageFilters, page: PageRequest }`, `MessageFilters { unread_only, flagged_only, has_attachments, from_contains: Option<String>, since: Option<Timestamp>, until: Option<Timestamp> }` ; `list_messages(db, accounts_of_profile, query) -> Page<MessageSummary>` :
   - `ViewRef::Mailbox` : messages ayant une apparition non supprimée dans la boîte ;
   - `StandardView::Unified` : messages ayant une apparition dans une boîte de rôle `Inbox`, **tous comptes du profil** (7.10), un message n'apparaît qu'une fois (S11) ;
   - `Unread` / `Flagged` : tous comptes, selon les drapeaux du message.
   - Tri `sort_date DESC, id DESC`, curseur opaque, limite bornée (invariant 29).
2. `get_message(id) -> MessageSummary` ; `get_body(id) -> BodyView` où `BodyView { text: String, html_available: bool }` si le corps est présent, sinon erreur `incompatible_state.body_unavailable_offline` (S6) — le téléchargement est une **commande réseau explicite séparée** (`FetchBody`, tâche longue, J8) ; `get_raw_source(id) -> Vec<u8>` (même règle) ; `list_attachments(id)`.
3. Recherche locale : `search(query: &str, filters, page)` → FTS5 + filtres (expéditeur, destinataire, période, pièce jointe, boîte, drapeau).
4. Fils (D-15, invariant 13) : `threads::thread_key(summary) -> String` : premier élément de `References`, sinon `In-Reply-To`, sinon `Message-ID` du message, sinon `subject:<objet normalisé>` (retrait répété des préfixes `Re:`, `RE:`, `Fwd:`, `Fw:`, `TR:`, `AW:`, `WG:`, `Réf :`, espaces, casse) ; si le message a un `thread_hint` serveur et aucun en-tête de réponse, `hint:<valeur>`. `assign_thread(tx, account, summary, hint) -> ThreadId` ; `recompute_threads(account)` (supprime et recalcule tout : sans perte, invariant 13). Lecture : `list_threads(mailbox, page)`, `get_thread(id) -> (Thread, Vec<MessageSummary>)`.
   - Rattachement : un message dont le `In-Reply-To` désigne un message déjà connu rejoint le fil de ce message (même si sa racine diffère).
5. Compteurs de boîte (lus/non lus) cohérents après chaque modification.
6. Tests : `scenario_s6_read_offline_body_present_or_unavailable`, `invariant_12_mark_read_applies_to_message_once` (vue unifiée), `invariant_13_threads_recomputed_identically`, `invariant_27_reads_never_touch_network` (aucune connexion au faux serveur pendant une batterie de lectures), `invariant_29_unified_view_paginates_without_duplicates`, fils (réponse, transfert sans en-tête, objet normalisé, indice serveur), recherche avec filtres, **performance** : 100 000 messages insérés, une page de liste en < 50 ms (test marqué `#[ignore = "perf : lancé par ci.sh --perf"]` **interdit** : à la place, test normal avec 20 000 messages et seuil proportionné, et une mesure à 100 000 dans `docs/ETAT/TESTS.md`).

## J7 — File d'actions, brouillons, envoi

Références : D-14, D-17, D-23, D-25, 8.6, 9.9, 9.10, 10.7, 10.8, 10.9, 12.2.2–3, 12.7 ; décision de départ 9 (envoi interrompu) ; S7, S8, S9, S10 ; invariants 17, 18, 19, 22, 26, 28.

Modules `mira-core/src/actions/`, `mira-core/src/drafts/`, `mira-core/src/send/`, `mira-core/src/smtp/`.

1. **Soumission** (`actions::submit`) : vérifie la cible (messages du compte), refuse ce qui est impossible **avant** de mettre en file (D-17 : `AddToMailbox` sur un compte à dossiers → `incompatible_state.multiple_labels_unsupported` ; boîte système à supprimer ou renommer → `incompatible_state.system_mailbox`) ; puis, **dans une seule transaction** : `enqueue` idempotent (même clé → même `ActionId`, aucun second effet, invariant 18), application de l'**effet local** (drapeaux, apparitions, compteurs) et mémorisation de l'inverse (`undo_json`), cibles serveur mémorisées (`server_targets_json` : boîte + UIDVALIDITY + UID, et identifiant stable). Rend `ActionId` sans attendre le réseau (invariant 28). Événement `ActionQueued`. Délai d'annulation : 5 s (`not_before = now + 5 s`).
2. **Rejeu** (`actions::replay(ctx, client)`) : tant que `next_ready` renvoie une action, dans l'ordre `seq` (invariant 19) : `InProgress` persistant → exécution serveur → `Succeeded` + `ActionApplied`. Traduction (9.9) selon `ProviderQuirks` et capacités :
   - marquer lu/suivi → `+FLAGS`/`-FLAGS` sur **toutes** les apparitions (D-14) ;
   - déplacer → `MOVE` si capacité, sinon `COPY` + `\Deleted` + `UID EXPUNGE` (ou pas de purge sans UIDPLUS, 10.14) ;
   - archiver → `RemoveFromInbox` (libellés : retirer `\Inbox`) ou `MoveToArchiveMailbox` (boîte de rôle Archive ; absente → `server.mailbox_missing`) ;
   - corbeille → déplacer vers la boîte de rôle Trash ; supprimer définitivement → `\Deleted` + `UID EXPUNGE` ; spam → déplacer vers Junk (ou vers Inbox pour « non spam ») ;
   - ajouter / retirer d'une boîte → libellés (`+X-GM-LABELS` / `-X-GM-LABELS`) ; sur un compte à dossiers, « retirer de sa seule boîte » = archiver ;
   - créer, renommer, supprimer, vider une boîte.
   - Avant de rejouer une action non idempotente (déplacement), **vérifier l'état serveur** (le message est-il déjà dans la cible ?) pour ne pas produire deux effets (10.7, invariant 18).
3. **Erreurs** : passagère (réseau, `retryable`) → `record_failure` (tentatives + 1, `not_before` avec backoff), reste `Pending` ; authentification → compte `AuthRequired`, action **reste en file** (S10) ; définitive (message absent du serveur, refus, quota) → `Failed`, **effet local annulé** via `undo_json`, événement `ActionFailed { code, reason }` (invariant 22, S8).
4. **Rebase** (D-23) : `reapply_pending_local_effects(account)` réapplique l'effet local des actions `Pending`/`InProgress` après qu'une synchro a écrasé le miroir avec l'état serveur.
5. **Annulation** : `cancel(action)` possible tant que l'action est `Pending` (dans son délai) : `Cancelled`, effet local annulé, `ActionCancelled` ; sinon `incompatible_state.action_not_cancellable`. `retry(action)` remet une action `Failed` en `Pending`.
6. **Brouillons** (`drafts/`) : créer (neuf, réponse, répondre à tous, transfert : destinataires, objet `Re:`/`Fwd:`, `In-Reply-To`/`References` à partir du message d'origine), modifier, joindre/retirer une pièce jointe (lecture d'un fichier local donné par le client, taille max 25 Mo), supprimer. L'identité par défaut du compte est utilisée si aucune n'est donnée. `SaveDraft` (copie dans la boîte Drafts du serveur, 8.2) : action facultative.
7. **Envoi** (`send/`, 10.8, S9) : `send(draft, at: Option<Timestamp>, key)` → action `Send` avec `not_before = at` ou `now + 10 s` (annulation d'envoi) ; brouillon en `Scheduled` ; `SendScheduled`. Annuler pendant le délai → brouillon revient en `Editing`. À l'exécution : **persister `InProgress` (tentative en cours) avant SMTP**, construire le MIME (`mail-builder`) avec un `Message-ID` généré par le moteur et mémorisé dans l'action, SMTP (`smtp/` encapsule `lettre` ; clair seulement vers la boucle locale ; XOAUTH2 ou mot de passe), puis si `!server_saves_sent_copy` → `APPEND` dans la boîte Sent (`SentCopyStored`) ; `SendDeparted` ; suppression du brouillon ; `Succeeded`.
   - **Reprise après plantage** (décision 9, invariant 26) : au démarrage, toute action `Send` en `InProgress` est vérifiée : recherche du `Message-ID` dans la boîte Sent (recherche serveur `HEADER Message-ID`) → trouvé : `Succeeded` ; sinon `Uncertain` + `SendUncertain` ; **jamais de renvoi automatique**. `resolve_uncertain_send(action, resend: bool)` : l'utilisateur décide.
   - Erreurs SMTP : 4xx → passagère ; 5xx (`552` trop gros → `server.message_too_large`, autre → `server.rejected`) → définitive, brouillon revient en `Editing`, `SendFailed`.
8. **Tests** : `scenario_s7_move_offline_then_replay_in_order` (avec et sans MOVE), `scenario_s8_action_on_deleted_message_fails_and_reverts`, `scenario_s9_send_with_undo_then_send`, `scenario_s10_token_expired_keeps_actions_queued`, `invariant_17_action_written_before_attempt`, `invariant_18_replay_after_crash_has_single_effect`, `invariant_19_actions_replayed_in_submission_order`, `invariant_22_definitive_failure_reverts_local_effect`, `invariant_26_interrupted_send_becomes_uncertain_never_resent` (faux SMTP `drop_after_data_once` + redémarrage), `invariant_28_write_returns_without_network` (compte hors ligne), copie dans Envoyés selon `server_saves_sent_copy`, D-17 refusé, annulation d'envoi.
