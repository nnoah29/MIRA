# Traduction de l'interface

Le **français est la langue source** : chaque texte de l'app est écrit en français et sert de clé de
traduction. `t('Texte')` rend le texte dans la langue active, `tn(n, 'message', 'messages')` gère le
singulier / pluriel, `{0}`, `{1}`… sont remplacés par les arguments.

## Règles pour le code

- Tout texte visible passe par `t()` (ou `tn()`). Jamais de texte français en dur dans un widget.
- Un texte stocké dans une donnée ou une constante, affiché plus tard par `t(valeur)`, se déclare avec
  `tkey('Texte')` pour que l'audit le compte.
- Dans un contexte constant (`const`), où `tkey()` est impossible : `// i18n:key N` sur la ligne (N : rang du
  littéral à déclarer) ou un bloc `// i18n:keys-begin` … `// i18n:keys-end` d'entrées `'code': 'texte'`.
- Un texte français qui ne doit pas être traduit (motif de recherche, nom d'exemple, journal…) porte
  `// i18n:ignore` sur sa ligne ; un fichier de contenu fictif entier, `// i18n:ignore-file` en tête.
- Les messages d'erreur du moteur sont traduits par code d'erreur (`lib/i18n/engine_errors.dart`), jamais
  affichés tels quels.

## Ajouter une langue (exemple : l'allemand)

1. `python3 tools/i18n-audit --init de` crée `app/lib/i18n/lang/de.dart` avec tous les textes, valeurs vides.
2. Ajouter une ligne à l'enum `AppLang` (`lib/i18n/i18n.dart`) :
   `de('de', 'de_DE', 'Deutsch', deStrings, 'en'),` — le dernier argument est la langue de repli : un texte
   resté vide s'affiche dans cette langue, puis en français. `null` : repli direct sur le français.
3. Traduire les valeurs dans `de.dart`. Un texte vide n'est pas traduit (repli), jamais une erreur.
4. `python3 tools/i18n-audit --lang de` liste ce qui manque ; le sélecteur de langue des réglages, les
   locales Material et le format des dates se déduisent de l'enum, rien d'autre à brancher.

5. Paquet Linux (vérifié par l'audit) : ajouter `GenericName[xx]`, `Comment[xx]` et `Keywords[xx]` à
   `packaging/common/io.github.nnoah29.Mira.desktop`, puis un `<summary xml:lang="xx">` et, après chaque
   `<p>` / `<li>` de `<description>`, sa version `xml:lang="xx"` dans
   `packaging/common/io.github.nnoah29.Mira.metainfo.xml`. Le nom « MIRA » ne se traduit pas.

## Vérifier

`python3 tools/i18n-audit` rend 0 quand chaque texte utilisé est traduit dans chaque langue, que les
paramètres `{n}` concordent, qu'aucune traduction n'est inutilisée et qu'aucun texte français n'est écrit en
dur ; `./ci.sh` le lance. Dans `flutter test` :

- `test/i18n_coverage_test.dart` : lance l'audit, vérifie que chaque code d'erreur du moteur a un texte
  (lu dans le vocabulaire Rust) et le repli entre langues ;
- `test/i18n_render_test.dart` : affiche l'app en anglais et échoue si un texte à l'écran est resté en
  français alors qu'il a une traduction.

## Limites connues

- Les pluriels suivent le modèle « un / plusieurs » (`tn`) ; une langue à plusieurs formes de pluriel
  demandera d'étendre `tn`.
- Les messages fictifs de la démonstration (`lib/data/seed.dart`, `documents.dart`) sont traduits comme le
  reste ; changer de langue en démonstration les reconstruit (les changements faits dans la démo sont perdus).
- Les noms propres des expéditeurs fictifs (« Équipe KERNEL », « Équipe MIRA ») ne sont pas traduits.
