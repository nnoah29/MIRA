## MIRA 2.3.1

2.3.1 is the first published build of the 2.3 line: the 2.3.0 tag was never released because its Linux packages failed to build (a renamed icon file was missed). Nothing else changed.

MIRA now has a real Windows installer and a background daemon on Windows, and every platform shares a single application identifier.

### What's new
- **Windows installer.** `mira-mail-2.3.1-windows-x64-setup.exe` installs for the current user only (no administrator rights), adds a Start menu shortcut, bundles the Visual C++ runtime and uninstalls cleanly. Uninstalling keeps your data. The portable `.zip` is still published. Both are unsigned, so Windows SmartScreen will warn on first launch.
- **Background daemon on Windows.** `mira-daemon.exe` ships next to the app, listens on loopback TCP with the local token, and the app starts it on demand. New-mail notifications are shown as Windows toasts, and clicking one opens MIRA.
- **Windows tray icon.** *Open MIRA*, a status line and *Quit MIRA* in the taskbar notification area.
- **Start at login (Windows).** On first launch the app asks whether to keep MIRA active in the background. Answering yes adds MIRA to the per-user startup list; you can change it later in Settings → Notifications.
- **MIRA icon on Windows.** The executable and the daemon now carry the MIRA icon instead of the Flutter default.

### Application identifier
- The identifier is now `com.toffanoah.mira` on Linux, Windows and Android (it was `io.github.nnoah29.Mira` on Linux and Windows, and `n.noah.mira` on Android). Desktop entry, AppStream metadata and notification identity follow.
- **Android:** this is a different app for Android. Uninstall the old build first; accounts and mail come back from your servers, but local settings, local labels and unsent drafts are lost.
- **Linux:** the app's own preferences (theme, accent colour, the background question) are stored per identifier and start fresh once. Your accounts and mail are not affected.

### Packaging
- Flatpak and Snap are dropped for good, and the AppImage is no longer published. Linux builds are the `.deb`, `.rpm`, `.tar.gz`, the Arch/AUR package and `install.sh`.

### Known limits
- Windows support is experimental: no code signing yet, and the daemon, tray and toasts have only been exercised by automated tests.
- Turning off "keep MIRA active" on Windows does not stop a daemon that is already running; use *Quit MIRA* in the tray icon.
- Android APKs are still signed with the debug key: fine for direct installs, not for the Play Store.
