# J7a — Client SMTP et authentification (OAuth2 PKCE, rafraîchissement)

Références : 7.7 (secrets, rafraîchissement silencieux), 10.8 (envoi), 15.2 (PKCE + boucle locale), annexe H (client SMTP, réseau), S1, S10 ; AG-03 (clair seulement vers la boucle locale) ; testkit : `mira_testkit::smtp::FakeSmtpServer`, `mira_testkit::oauth::FakeOAuthServer` (voir leur code et leurs tests), décisions AG-09.

## 1. `mira-core/src/smtp/` (encapsule `lettre`)

```rust
pub enum SmtpCredential { Password(SecretValue), XOAuth2(SecretValue) }
pub struct SmtpLogin { pub user: String, pub credential: SmtpCredential }
pub struct OutgoingMessage { pub from: String, pub recipients: Vec<String>, pub raw: Vec<u8> }   // enveloppe + message MIME complet
pub async fn send_message(endpoint: &ServerEndpoint, login: &SmtpLogin, message: &OutgoingMessage) -> Result<(), MiraError>;
```

- `Security::Tls` → TLS implicite (465) ; `StartTls` → STARTTLS (587) ; `Plaintext` → seulement vers la boucle locale, sinon `tls.plaintext_refused` (AG-03). Pas d'`openssl` : features `lettre` `tokio1-rustls-tls` (déjà dans le workspace ; vérifier qu'elles compilent sans `aws-lc`, sinon utiliser `rustls` avec `ring` et le signaler).
- XOAUTH2 : mécanisme `lettre::transport::smtp::authentication::Mechanism::Xoauth2`.
- Conversion des erreurs : connexion impossible → `network.unreachable` ; coupure sans réponse après DATA → `network.connection_lost` **marquée « issue incertaine »** (le moteur ne sait pas si le message est parti : 10.8) — expose `SmtpOutcomeUncertain` via un code dédié ou un champ : utilise le code `network.connection_lost` avec `retryable = false` et documente-le ; `535` → `authentication.rejected` (XOAUTH2 : `authentication.token_expired`) ; `4xx` → `server.rate_limited` ou `server.rejected` avec `retryable = true` ; `552` → `server.message_too_large` ; autre `5xx` → `server.rejected` (définitif). Jamais de secret dans un message.
- Construction du message (`mira-core/src/send/compose/` ou `smtp/build.rs`) : `build_message(input: &ComposeInput) -> Result<BuiltMessage, MiraError>` avec `mail-builder` : `From` (nom + adresse de l'identité), `To`/`Cc`/`Bcc` (les `Bcc` ne figurent **pas** dans les en-têtes, seulement dans l'enveloppe), `Subject`, `Date`, `Message-ID` fourni par l'appelant (`<id@mira.local>` généré par le moteur), `In-Reply-To`/`References`, partie texte, partie HTML facultative, pièces jointes. `BuiltMessage { raw: Vec<u8>, message_id: String, envelope_recipients: Vec<String> }`.

## 2. `mira-core/src/auth/` (OAuth2 + mots de passe)

- `OAuthFlow` (machine à états explicite : `AwaitingRedirect` → `CodeReceived` → `TokensObtained`, ou `Cancelled` / `Failed`) :
  - `start_flow(settings: &OAuthSettings, client_id: &str, login_hint: &str, rng) -> Result<PendingFlow, MiraError>` : génère `code_verifier` (43–128 caractères non réservés, aléatoires : `rand`), `code_challenge = BASE64URL(SHA256(verifier))` sans remplissage (`sha2`, `base64`), `state` aléatoire, ouvre un `tokio::net::TcpListener` sur `127.0.0.1:0`, construit l'URL d'autorisation (`response_type=code`, `client_id`, `redirect_uri=http://127.0.0.1:<port>/callback`, `scope` séparés par des espaces, `state`, `code_challenge`, `code_challenge_method=S256`, `login_hint`, `access_type=offline` facultatif) avec encodage URL correct. Renvoie `PendingFlow { authorize_url, … }` (le verifier reste en mémoire, **jamais** journalisé ni affiché par `Debug`).
  - `wait_for_redirect(&mut PendingFlow, timeout) -> Result<AuthorizationCode, MiraError>` : accepte **une** connexion, lit la requête `GET /callback?code=…&state=…` (ou `error=access_denied` → `authentication.oauth_cancelled`), vérifie `state` (`authentication.oauth_state_mismatch`), répond une petite page HTML « vous pouvez fermer cette fenêtre » (sans JavaScript), ferme l'écouteur. Délai dépassé → `network.timeout`.
  - `exchange_code(token_url, client_id, code, verifier, redirect_uri) -> Result<TokenSet, MiraError>` : `reqwest` (`rustls-tls`, déjà au workspace) POST `application/x-www-form-urlencoded` ; réponse JSON `{access_token, refresh_token?, expires_in?, token_type}` → `TokenSet { access_token: SecretValue, refresh_token: Option<SecretValue>, expires_at: Option<Timestamp> }` ; erreur `invalid_grant` → `authentication.token_revoked` ; autre → `authentication.rejected`.
  - `refresh_tokens(token_url, client_id, refresh_token) -> Result<TokenSet, MiraError>` (rafraîchissement silencieux, 7.7) ; `invalid_grant` → `authentication.token_revoked` (le compte passera `AuthRequired`, S10).
  - Les URL `token_url` vers autre chose que `https://` ne sont acceptées que vers la boucle locale (testkit) — même règle qu'AG-03.
- `CredentialVault` (au-dessus de `SecretStore`) : `store_password(profile, account, &SecretValue)`, `store_tokens(profile, account, &TokenSet)`, `load_imap_login(account, auth_kind, user) -> ImapLogin`-compatible (renvoie le `SecretValue` du mot de passe ou du jeton d'accès), `delete_all(profile, account)` (les trois `SecretKind`), `access_token_expired(account, now)` (l'expiration est stockée… **pas** en base en clair avec le jeton : stocke `expires_at` dans le trousseau sous `SecretKind::AccessToken` ? Non : stocke-la dans une table de configuration `account_token_meta(account_id, expires_at)` via une migration `v00N` — ce n'est pas un secret).
- Tests (contre `FakeOAuthServer` et `FakeSmtpServer`, sur 127.0.0.1) : flux complet PKCE (`approve` simule le navigateur) → jetons rangés dans un `MemorySecretStore` ; `state` modifié refusé ; refus utilisateur (`deny`) → `oauth_cancelled` ; délai dépassé ; rafraîchissement ; jeton révoqué → `token_revoked` ; URL d'autorisation correctement encodée (le `code_challenge` correspond au verifier) ; le `Debug` d'un flux ou d'un `TokenSet` ne contient aucun secret ; SMTP : envoi complet reçu par le faux serveur (expéditeur, destinataires dont Bcc, Bcc absent des en-têtes, `Message-ID` présent) ; AUTH refusé ; XOAUTH2 avec jeton émis par le faux OAuth ; `fail_next("552 …")` → `server.message_too_large` ; `drop_after_data_once` → `network.connection_lost` non réessayable ; clair vers un hôte non local refusé.
